關 6

留下版本，換一台電腦也能接著做

GitHub 在這一關先拿來做版本控制與跨機器接手。每次修改都留一個版本，專案規格、規則與交接紀錄也跟著走；把網站部署成網址是另一件事，最後再選要不要做。

名詞先講白話

Git：替專案保存每次修改的版本。
GitHub：把 Git 版本庫放到網路上，讓另一台電腦或協作者取得同一份專案。
commit、push：把目前修改「存成一版」，再「傳到 GitHub」。
clone、pull：另一台電腦第一次取得完整專案用 clone；已經有專案時，用 pull 抓回最新版本。

1

這關做什麼

把專案變成一條看得見的版本線，並讓另一台電腦讀到同一批專案記憶。

電腦 A 更新去識別化學員記憶與核准共享的工具
  ↓ 先看差異
commit 存成一版 → push 傳到 GitHub
                         ↓
電腦 B：第一次 clone／之後 pull
  ↓
讀 PROJECT-README、HANDOFF、LEARNER-RULES 與 specs
  ↓
從同一個進度接著做

這裡說的「專案記憶」，不是上一台電腦的聊天內容，而是你主動寫進檔案、取得 repo 權限的人都讀得到的去識別化紀錄。學員專案只使用：

  • PROJECT-README.md：這個學員專案的目標、固定位置與目前狀態
  • HANDOFF.md：做到哪裡、下一步與仍待問誰
  • LEARNER-RULES.md：個資、安全與寫作偏好
  • specs/step1.md 至 step5.md：每關確認過的來源、規格與待確認事項

教材製作者的 AGENTS.md、README.md、協作指南、查證資料與改善工單，不是學員專案記憶，不要複製到 club2026-share，第二台 AI 也不要讀它們當待辦。

GitHub 不會自動搬走聊天記錄

AI 的聊天內容、瀏覽器暫存與 localStorage 不會因為 push 就跑到另一台電腦。要跨機器接手的資訊，必須整理成 repo 裡的規格、規則或交接檔。這些檔案同樣不准放真實學生個資。

行前要準備（併入行前信）

  • GitHub 帳號（免費，建議用可長期使用的個人信箱註冊）
  • 安裝 Git 與 GitHub CLI，並完成 GitHub CLI 登入；這是讓 AI 自動建立版本庫、commit、push、clone 與 pull 的行前工具
  • GitHub Desktop 是有畫面的選配工具，不是 AI 自動流程的必要條件

第二台電腦也要先準備

  • 安裝 Git 與 GitHub CLI，並用同一個有權限的 GitHub 帳號完成 gh auth login
  • 準備一個空的存放位置，不要挑已經有同名專案或做到一半檔案的資料夾
  • 先記下 Private repo 的 HTTPS 網址；第二台第一次取得專案時一定要用到

10 分鐘講師機示範

時間做什麼你會看到什麼
0:00–1:30打開乾淨接力資料夾，指出 PROJECT-README.md、HANDOFF.md、LEARNER-RULES.md 與 specs/知道哪些學員記憶能跟著 repo 走
1:30–3:30請 AI 先列出差異，再 commit、pushGitHub 留下一個有說明的版本

只有一台電腦也能示範

在另一個空資料夾執行 clone，把它當作「第二台電腦」。不要直接複製原資料夾；這樣學員才看得到 GitHub 如何把版本與專案記憶交給另一個工作位置。

2

官方要求

這一關不對應基金會的繳交文件。版本控制與跨機器接手，是團隊自己保護成果、維持工作連續性的做法。

會跟著 GitHub 走不會自動跟著走絕對不要上傳
逐檔核准的空白 HTML 工具、去識別化摘要與學員記憶 AI 聊天記錄 學生姓名、學號、電話、地址與照片
PROJECT-README、HANDOFF、LEARNER-RULES、specs 與其他已核准的去識別化檔案 未 commit、只 commit 未 push、未追蹤或被 .gitignore 排除的檔案；瀏覽器 localStorage、AI 對話／session、本機設定與登入 token 密碼、API 金鑰、登入憑證、備份-*.json，以及含個資的匯出檔

repo 設為 Private 也不代表可以放學生個資。Git 會保留歷史版本，推上去之後才刪檔，舊版本裡仍可能找得到。

跨機器接手不等於搬走全部原件

sources/ 與真人資料不進 GitHub。第二台可以接著讀規格、修改安全工具、看進度；需要重新核對官方或校內原件時，必須由學校用核准方式另行提供，缺原件就只能標「待確認」。

提示詞卡

前提：行前那三個工具要裝好

這一關要 AI 幫你做事，它需要三樣東西：Git（版本與傳送）、 GitHub CLI（讓 AI 登入、建立並操作 GitHub repo）、還有你已經登入過一次的 GitHub 帳號。 三樣都在 行前安裝 那頁的第 06、07 項。
如果沒裝 GitHub CLI，AI 常會回報找不到 gh 指令，無法替你建立或管理 GitHub 上的 repo； commit、push、clone、pull 本身則是 Git 的工作。

第一次 commit 前，AI 還要檢查 Git 的作者姓名與 email。若尚未設定，請它停下來問你要用什麼；不要讓它自行填寫，也不要未經同意改全域設定。

第一步不是上傳，是先做乾淨接力資料夾

club2026 可能放著校務原件、真名備份或不該分享的工作資料。不要叫 AI 掃描原始工作資料夾，也不要整包推上 GitHub。先更新學員記憶，再用檔案總管或 Finder 手動建立 club2026-share，逐項複製下方核准的內容。

4

新手會卡在哪

  • 第一次 push 要登入授權，瀏覽器會自己跳出來 → 正常，照著按就好。
  • 第一次 commit 報作者身分不明 → 請 AI 顯示目前設定，停下來問你要用的姓名與 email；不要讓它自行猜，也不要未經同意改全域設定。
  • 把 commit 和 push 當成同一件事 → commit 只存到這台電腦；完成 push，另一台才抓得到。
  • 換電腦後直接 pull → 先請 AI 檢查本機有沒有未保存的修改；有就停下來處理，不要硬蓋。
  • 以為 AI 記得上一台的聊天 → 把需求、規則與下一步寫進 repo 的專案記憶檔，再 commit、push。
  • 第二台已經有同名資料夾就直接 pull → 先用 git remote -v 比對 repo 網址，再看 git status；任一不符就停。
  • 只寫「更新」當 commit 訊息 → 改成具體說明，例如「補上出席表驗收規則，避免漏算請假」。
  • 第二台只說「幫我抓下來」 → AI 不知道是哪個 repo、要放哪裡。一定要貼 repo HTTPS 網址與目的地完整路徑。
🚨 上傳前先擋個資與憑證

GitHub 會保留版本歷史。即使 repo 是 Private，或之後把檔案刪掉，舊版本仍可能留著。專案記憶只能寫工作規格與交接資訊，不能寫真實學生資料。

需要共享範例時，另外準備一個乾淨資料夾，只放虛構資料與可公開的檔案。真名單留在學校核准的系統或安全位置。

push 前一定要先問 AI 這一句（不要跳過）：

先不要上傳。請先做兩件事：
一、列出你打算上傳的每一個檔案（含隱藏檔），一個一行。
二、逐檔告訴我裡面有沒有出現這些東西：姓名、學號、班級座號、
    電話、email、地址、生日、照片裡的人臉、家長資料、成績、出席、請假、
    個別回饋或私訊、身分證、戶籍、匯款資料、密碼、API 金鑰、備份-*.json。
我確認之後你再上傳。

它列完你自己看一遍，有真名就停下來。東西一旦推上去，就算你之後刪掉，紀錄裡還是留得住
